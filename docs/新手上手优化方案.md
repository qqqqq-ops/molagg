# FlowMuse 新手上手优化方案

> 目标：让第一次打开 `localhost:3001` 的人，**不看文档、不问人，5 分钟内生成出第一个作品**。
> 参考对象：`app.havemango.cc`（AI影音飓风）—— 一个 uni-app + uniCloud 的商业 AI 视频工作台。
> 参考方式：前端分包拆解（非猜测），下面的结论均来自其 `/assets/*.js` 实际代码。

---

## 一、参考站到底做对了什么

### 1.1 它的页面是"声明式三层壳"，一个频道页只有 10 行

`/pages/workbench/video-channel-f` 的完整实现（去混淆后）：

```js
WorkbenchShell  active-path="/pages/workbench/video-channel-f"  title="创作视频"
└─ VideoEngineView  active-engine="seedance-f-channel"
                    engine-name="F 渠道即梦 Seedance 2.0"
                    engine-code="F-CHANNEL / VIDEO"
   └─ ChannelGenerationForm  channel="f"
```

全站 14 个视频频道页（`index / b / n / f / m / nx / g / p / coo / x / o / fy / ab / hurricane`）
**每一个都只是这 10 行里换 3 个字符串**。所有逻辑集中在 3 个共享组件里：

| 组件 | 体积 | 职责 |
|---|---|---|
| `WorkbenchShell` | 10 KB | 侧栏导航、公告、服务健康灯、积分、主题切换 |
| `VideoEngineView` | 17 KB | 引擎（渠道）切换器 + 待生成队列 |
| `ChannelGenerationForm` | 65 KB | 唯一的生成表单，按 `channel` 差异化 |

**对照 FlowMuse**：`SimplifiedCreateContent.tsx` 单文件 **3439 行 / 62 个 `useState`**，
图片和视频靠 `activeTab` 在同一组件里分叉，MJ / 豆包 / 万相 的参数全部平铺在同一棵树上。

### 1.2 "生成模式"是唯一的分叉开关

参考站表单顶部第一个字段就是 **生成模式**，四选一：

```
文生视频 │ 首帧生成 │ 尾帧生成（首尾帧） │ 多模态生成
```

选完才显示对应的上传区 —— `文生视频` 不显示任何上传框；`首帧生成` 只显示"选择首帧图片"；
`多模态生成` 才出现"参考图片 / 视频参考 / 音频参考"。

**对照 FlowMuse**：`create.json` 里有 **15 个** 上传区 label
（`labelDoubaoFrames20`、`labelWanxReferenceVideos`、`labelWanxDrivingAudio`、
`labelWanxVideoContinuation` …），按 provider 硬分支，全部堆在同一页，
还要靠提示文案解释互斥关系："注意：豆包的参考图与首尾帧只能二选一"。
—— 新人读到这句就已经放弃了。

### 1.3 表单字段被压到固定 5 个

```
生成模式 · 模型 · 分辨率 · 视频比例 · 视频时长
```

往下才是折叠的「生成选项」，而且开关全是**二元明示**，不是抽象 switch：

```
生成音频 / 不生成音频      返回尾帧 / 不返回尾帧      联网搜索 / 不联网搜索
```

比例选项也带人话后缀：`16:9 横屏`、`9:16 竖屏`、`21:9 超宽屏`、`自适应素材`。

### 1.4 点"生成"之前就知道会发生什么

- 按钮上方常驻：**本次预计消耗 N 积分**、`普通价 N 积分`、`提交时云端再次核验`
- 计费方式明示：`按秒计费` / `按次计费`
- 按钮文案是 **`确认并生成`**，不是光秃秃的"生成"
- 校验信息全是人话：`请选择生成模式`、`首帧生成必须选择一张图片`、
  `尾帧生成必须各选择一张首帧和尾帧图片，系统按顺序提交`

**对照 FlowMuse**：点生成是黑盒。没配 API Key 时 `SimplifiedModelSelector.tsx:50-54`
直接把下拉框 `disabled`，只留一句"暂无可用的图片模型"，**没有任何出口**。新人在这里彻底卡死。

### 1.5 导航全是动词短语

```
创作图片 · 创作视频 · 短剧画布 · 任务队列 · 批量任务 · 资产中心 · 开放 API
```

**对照 FlowMuse**：`画廊 · 创作中心（快速模式/工作流模式） · 画板 · 项目 · 任务`
—— 名词 + 抽象概念，且"画廊"点进去是"我的作品"（空的、还要登录）。

### 1.6 壳上有一颗服务健康灯

`WorkbenchShell` 里有三态：`检测中` / `服务正常` / `连接异常`。
对 FlowMuse 这种**自己填 Key**的开源程序，这颗灯比对商业站更重要 —— 一眼知道"我配对了没"。

### 1.7 预置提示词是"一键效果"，不是"模板分类"

参考站直接给成品效果名 + 完整长提示词，点一下即用：

```
干字形过人脸 · 拓扑线框网格 · 全身三视图 · 头部线稿化 · 斜线覆盖面部 · 多视角图彩铅画
```

**对照 FlowMuse**：「网络提示词」要先选分类（人物肖像/风景照片/产品摄影…）
→ 再选卡片 → 再点"使用此提示词"，三步才落到输入框。

### 1.8 其它值得抄的细节

- **待生成队列**：不是点一次生成一次，而是 `加入待生成队列` → 勾选 → `生成所选任务 · N 积分` → 依次生成
- **素材本地剪裁**：参考视频超时长，浏览器里先剪（`剪裁片段需为 X–Y 秒`）
- **重新制作 + 参数回填**：历史任务一键复现，且优雅降级 —— `原模型已不可用，已切换到当前渠道默认模型`

### 1.9 不要抄的部分

参考站是**商业聚合站**：积分体系、云端价格核验、`按秒计费`、开放 API 配额。
FlowMuse 是**本地优先 + 自带 Key**，没有积分概念。
对应位置应该换成：**渠道连通状态 + 预计耗时 + 该模型的官方计费说明链接**。

## 三、关键前提：FlowMuse 已经有"渠道"了

这是本方案成本最低的原因 —— **不需要新建任何数据模型**。

`frontend/src/lib/api/types/admin/channels.ts` 的 `Channel` 已具备：

```ts
{ id, name, provider, baseUrl, apiKey }   // + configured 状态
```

`settings.json` 里已有全套文案：`测试连接` / `连接正常` / `连接失败` / `已配置` / `未配置`。

**现状**：这些只活在 `SystemConfigModal` 的一个 tab 里（`ModelChannelManagerSection.tsx`）。
**改造**：把它从"设置项"提升为"导航入口"。这就是频道化的全部。

## 四、改造方案

### 阶段 A：打通第一次生成（不改架构，纯补出口）

| 改动 | 文件 | 说明 |
|---|---|---|
| A1 | `SimplifiedModelSelector.tsx:50-54` | 模型为空时，把 disabled 下拉换成 **「⚙️ 去配置模型渠道」按钮**，直接开 `SystemConfigModal` 并定位到渠道 tab |
| A2 | 新增 `components/shared/FirstRunGuide.tsx` | 检测"零已配置渠道"→ 创作页顶部常驻三步卡片：① 注册 ② 配置渠道 Key ③ 点样本生成 |
| A3 | `Sidebar.tsx` 底部 | 加一颗**服务健康灯**（复用 `测试连接`），三态：检测中 / 渠道正常 N 个 / 未配置渠道 |
| A4 | `App.tsx:171-183` | 未登录访问 gallery 不弹登录，改为示例占位 + "登录查看自己的作品" |
| A5 | `nav.json` / `gallery.json` | 「画廊」统一改「我的作品」；导航全部改动词：`创作图片` `创作视频` `我的作品` `任务队列` |
| A6 | `landingHomePage.shared.ts:21-27` | 外链背景换成 `public/images/` 本地资源 |
| A7 | `GalleryContent.tsx` | 卡片加 `onClick` → 大图预览 + 下载 |

> A1 是单点收益最高的一条 —— 它是新人卡死的**那一步**。

### 阶段 B：频道化入口（照搬参考站的三层壳）

**B1. 建立三层壳**，把 3439 行拆成：

```
WorkspaceShell            ← 由现有 ConditionalLayout + Sidebar 演进
└─ ChannelView             ← 新增：渠道切换器（读 channels 列表）
   └─ ChannelGenerateForm  ← 由 SimplifiedCreateContent 瘦身而来
```

**B2. 路由从"按功能"改为"按渠道"**（`App.tsx:185` 附近）：

```
/zh-CN/create                     →  /zh-CN/create/image/:channelId
/zh-CN/create?mode=video          →  /zh-CN/create/video/:channelId
```

渠道列表直接来自已有的 `channels` API —— 用户配了哪个渠道，侧栏就出现哪个入口。
**未配置的渠道显示为灰色 + "点击配置"**，这样配置入口自然长在导航上，A2 的引导卡片长期可退役。

**B3. 引入「生成模式」作为唯一分叉开关**，替换现在按 provider 硬分支的 15 个上传 label：

```
文生图 / 图生图                          （图片）
文生视频 / 首帧生成 / 首尾帧生成 / 多模态  （视频）
```

`create.json` 里那批 `labelDoubao*` / `labelWanx*` 全部收敛进模式定义表：

```ts
// lib/constants/generationModes.ts
{ mode: 'first-frame', label: '首帧生成', uploads: ['firstFrame'], hint: '上传 1 张图片，视频从这张图开始' }
```

**B4. 首屏字段压到 5 个**：`生成模式 · 模型 · 分辨率 · 比例 · 时长`。
其余（负向提示词、MJ 的 `--q/--s/--c/--weird/--iw`、种子、项目上下文）全进「进阶」折叠。
开关文案改二元明示：`生成声音 / 不生成声音`。

**B5. 生成按钮上方加确定性信息**：
`当前渠道：XX（连接正常）· 预计 40-60 秒 · 结果存到本地 uploads/`
按钮文案 `生成` → `确认并生成`。

### 阶段 C：锦上添花

- C1 提示词库改「一键效果」：给成品效果名 + 内置完整长提示词，点一下直接落输入框（去掉选分类这一步）
- C2 待生成队列：`加入队列` → 勾选 → `依次生成`
- C3 历史任务「重新制作」+ 参数回填，模型失效时降级到该渠道默认模型
- C4 拆 `SimplifiedCreateContent.tsx` 剩余部分为独立组件

## 五、执行顺序建议

```
A1 → A2 → A3 → A4/A5/A6/A7   （半天~1 天，立刻解决"卡死"）
      ↓
B1 → B2 → B3 → B4 → B5        （2~3 天，真正的频道化）
      ↓
C1 → C2 → C3 → C4             （按需）
```

阶段 B 的 B3（生成模式收敛）是**唯一需要仔细回归**的部分，因为它改写了各 provider 的参数组装路径。

# 附录：第二参考站 `aivideo.token6688.com`（Next.js SSR，拆包实证）

技术栈：Next.js App Router（`[locale]/(workspace)`，`data-skin="motion"`）。
页面 SSR 后是 `正在同步会话...` 的登录壳，但 flight payload 里带了 **9900 条中文 UI 串**，
足以还原产品结构。以下结论均来自这些实际字符串。

## A. 它和 havemango 对"渠道"的处理正好相反 ⚠️

| | havemango | token6688 |
|---|---|---|
| 渠道的地位 | **一级导航**，14 个频道页各自独立 URL | **高级设置**，默认不出现 |
| 默认行为 | 用户明确选「F 渠道 / S 渠道」 | `系统自动选择最优渠道`、`自动(按策略选)` |
| 失败处理 | 用户自己换频道 | `智能兜底`：`生成失败自动切换同类模型（图片/视频/文本）`，并留痕 `已从 {requested} 自动切换 · {reason}` + `自动切换记录` |
| 策略 | 无 | 三个模板：`优先成功率更高、更稳定的渠道` / `优先价格更低的渠道` / `优先选择返回更快的通道` |
| 手动指定 | 就是主流程 | 折叠在 `渠道 · 高级参数 · 创作模型` 里，`可多选`，`一条都不选则全渠道自动调度` |
| 记忆 | — | `渠道选择会保存为该模态的默认，下次生成沿用` |

**这对 FlowMuse 的含义**：FlowMuse 用户是**自己配 1~3 个渠道**的本地部署者，
不是在 14 个供应商之间比价的商业站用户。让他每次生成先选渠道 = 纯增负担。
→ **应该采用 token6688 的模型**：渠道自动调度 + 智能兜底，手动指定收进「高级」。

## B. 一级导航按"我要做什么"，不按"用哪条线路"

token6688 的入口全是**能力或场景**：

```
对话 · 图片 · 视频 · 音频 · 智能体 · 画布
电商工作台 · 漫剧工作台 · AI PPT · 短片工作台 · 3D 导演台 · 计费工作台
```

场景入口的文案全是**成果导向**：

```
一键电商 · 一键漫剧 · 一键换片 · 电商一键出图 · 一键成片快剪辑 · AI 模特试穿·一键上身
选一个功能开始 —— 图片 / 视频 / 文案，全链路一站上新
```

功能多到一定程度就直接给搜索框：`搜索功能或模式…`

## C. 复杂流程靠「节点 + 确认门 + 双模式」变得可上手

它最深的功能（导演流水线）用三招压住复杂度：

1. **切成节点**：`导演流水线 · {count} 节点`、`{done}/{total} 节点完成`
   故事蓝图 → 分段规划 → 主体识别/定妆图 → 关键帧提示词 → 关键帧 → 视频段 → 配音 → 拼合
2. **确认门**：`停在确认门 · 等你操作`、`开始这一步`、
   `上一步已完成。这一步会真实消耗额度，确认后才开始。`
3. **双模式随时切换**：`导演智能体全程托管`（自动跑完） ⇄ `每步生成好停下等确认`（逐步）
   —— `转智能托管` / `转逐步确认` 一键互换。新人用托管，熟手用逐步。

配套的**断点续跑**：`从本节点续跑, 复用上游不重扣`、`从失败处续跑`、`重试失败节点`。
即"出错不用从头来、不重复花钱"。

## D. 极其克制的预期管理（FlowMuse 完全缺失的一环）

```
预扣约 {cost} · 合计预估约 {cost} · 全片视频约 {cost}
实际扣费通常比预估高 15%–60%。可以现在开始，但中途余额用完会停在半路，已生成的部分不会退费。
建议余额比预估多留 50% 再开始，中途不够会停在半路。
估价没拿到，仍可开始
```

失败文案是教科书级的 —— **归因 + 免责 + 补偿 + 下一步**：

```
上游 AI 服务商通道短暂故障，与你的操作无关，本次失败算力已自动退还。
请稍后重试或切换其他模型。
```

对照 FlowMuse `errors.json`：`生成失败，请重试` / `轮询超时，请手动刷新`
—— 不告诉用户是谁的错、要不要重配 Key、能不能换模型。

## E. 上手引导是独立产品，不是一个 tooltip

```
第一次来？有一套课程带你从头上手，边看边做。
使用课程 · 从新手到进阶 —— 分新手小白、普通、进阶三个阶段
跟着引导做一遍 · 开始学习 · 从这里开始学
```

全站常驻 **帮助中心浮标**：右下角问号，**按 `?` 键**打开，可搜索。
每条错误提示末尾都挂一句 `可以点右下角的帮助中心浮标搜索，或联系在线客服`。

## F. 案例驱动上手 —— 对 FlowMuse 性价比最高的一条

```
看中哪张，一键「做同款」 · 一键复刻同款 · 选一个配方，一键做同款
从精彩案例开始 · 挑一个喜欢的作品，一键把它的提示词和素材复刻到当前创作
该作品类型与当前工作台不匹配（会做校验）
```

**FlowMuse 的现成条件**：已经有画廊、有 `task.parameters`（含 prompt / 模型 / 比例 / 尺寸）。
而现在画廊卡片**连 `onClick` 都没有**（`GalleryContent.tsx:67-110`），点了没反应。
→ 把卡片点击改成「做同款」= **顺手修掉一个 bug + 给新人一条最短上手路径**，一箭双雕。

## G. 空状态带方向指引，不是一句"暂无数据"

```
← 左侧上传商品图 + 选模特,一键出多张上身图。或切到「优秀案例」做同款。
素材与参数已备好，点「{action}」开始出{noun}；或在「优秀案例」继续挑模板做同款。
先去工作台生成一些素材 — 完成后会自动出现这里
去「{feature}」上传商品图, 或在素材库导入 —— 之后这里一键复用。
暂无历史会话，开始你的第一条任务吧。
```

每一句都包含**指向**（左侧 / 切到某处 / 去某功能）和**备选路径**（或者…）。

# 修正后的优化方向

## 方向性调整

上文第四章阶段 B 原方案（照搬 havemango 的"渠道即导航"）**需要修正**：
渠道化只适合渠道众多的商业聚合站。FlowMuse 应改为：

```
一级导航 = 我要做什么（创作图片 / 创作视频 / 我的作品 / 任务队列）
渠道     = 自动调度 + 智能兜底，手动指定收进「高级」
场景     = 后续可加的成果导向入口（一键做同款 / 电商图 / 分镜短片）
```

# 已定方向（拍板结果）

## 决定一：渠道走"折中" —— 默认自动，状态可见可切

**不做**成 havemango 的 14 个频道页导航，**也不**像 token6688 那样完全藏起来。

### 生成链路（用户感知）

```
简洁模式：完全看不到渠道。生成按钮上方一行：
          「渠道 XX · 连接正常 · 预计 40-60 秒」

高级模式：出现「指定渠道」多选。一条都不选 = 自动调度（默认）。
          选择结果记为该类型的默认，下次沿用。
```

### 侧栏「渠道状态」入口（这是折中的落点）

`Sidebar.tsx` 底部加一个入口，本身就是一颗**健康灯**，三态：

| 状态 | 显示 | 点击后 |
|---|---|---|
| 未配置任何渠道 | 🔴 未配置渠道 | 直开 `SystemConfigModal` 渠道 tab |
| 有渠道但连接失败 | 🟠 1/2 渠道异常 | 展开抽屉，异常项高亮，带「测试连接」 |
| 正常 | 🟢 2 个渠道正常 | 展开抽屉查看/切换优先级 |

抽屉内容（全部复用已有 API）：渠道名 · provider · 连接状态 · 可用模型数 ·
`测试连接` 按钮 · 设为优先 · **自动切换记录**。

> 这样渠道既没有污染主流程，又是一等公民 —— 新人靠那颗灯知道"我配对了没"，
> 熟手点进去能比价和切换。同时它天然替代了阶段 A 的 A2 引导卡片和 A3 健康灯。

### 智能兜底（A12 具体化）

```
生成失败（上游 5xx / 超时 / 该模型下线）
  → 自动切到同 provider 下同类型的其它可用模型，最多重试 2 次
  → 顶部 toast：「已从 seedream-4 自动切换到 seedream-3 · 原因：上游超时」
  → 记录进「自动切换记录」，可在渠道抽屉里翻
参数不合法 / Key 未配置 → 不兜底，直接报人话错误 + 给出口
```

## 决定二：创作页上「简洁 / 高级」双模式

**不做**完整的节点流水线 + 确认门（FlowMuse 目前是单步生成，没有多节点链路，用不上）。

### 简洁模式（默认，首次进入即此模式）

首屏只有四件东西：

```
① 生成模式 tab    图片：文生图 / 图生图
                  视频：文生视频 / 首帧生成 / 首尾帧生成
② 大输入框        描述主体、动作、镜头和风格（保留 @ 引用）
③ 常用比例 chip   16:9 横屏 · 9:16 竖屏 · 1:1 方形
④ [确认并生成]    上方一行：渠道 XX · 连接正常 · 预计 40-60 秒 · 存到 uploads/
```

**关键原则：简洁模式不是"隐藏参数"，而是"给参数合理默认值"。**
模型自动选该类型下第一个可用的推荐模型，模型名以小字显示在按钮旁，点击可换。
分辨率/时长/清晰度全部取模型默认档，不在首屏出现。

### 高级模式

现有的全部能力（负向提示词、MJ 的 `--q/--s/--c/--weird/--iw`、种子、
项目上下文、指定渠道、各 provider 的参考素材槽位）。

### 切换与记忆

- 右上角一个开关，文案二元明示：`简洁模式` / `高级模式`
- 选择存 `localStorage`，**首次访问强制简洁**
- 从简洁切高级时保留已填内容，不清空

### 与生成模式的关系

`生成模式` 是唯一的分叉开关（沿用 havemango 的做法），
替换掉现在 `create.json` 里按 provider 硬分支的 15 个上传 label：

```ts
// lib/constants/generationModes.ts
{
  mode: 'first-last-frame',
  label: '首尾帧生成',
  uploads: ['firstFrame', 'lastFrame'],
  hint: '上传首帧和尾帧两张图，AI 补中间运动',
  validate: '首尾帧模式至少需要 2 张图片，前两张依次作为首帧和尾帧',
}
```

模式对模型的兼容性检查也在这张表里做，报错给人话 + 出路：
`当前模型不支持首尾帧控制，可改用「首帧生成」或换支持的模型（可用：X / Y）`

## 2026-09-18 完成 A9 + A6

### A9 的实际问题和原方案不一样

原方案写的是「重写 `errors.json`」。动手时发现 **`errors.json` 里的 `tasks` / `network` /
`auth` 三段从来没有被任何代码引用过** —— 全项目只用到 `errors.notFound`。
光改那些字符串，界面上一个字都不会变。

真实的错误链路是：

```
后端 BadRequestException("请先配置 XX 渠道的 Base URL 和 API Key")
  → 拦截器包成 ApiClientError{ message, code }
  → 创作页 catch 里 toast.error(error.message || t('errors.submit'))
```

也就是说后端的归因文案本来就写得不错，前端也确实透出来了。
**真正缺的不是文案，是可操作性** —— 一个 8 秒后消失的 toast，
用户读完"请先配置渠道"也不知道去哪配。

### 做法

**新增 `frontend/src/lib/utils/failure.ts`** —— 只做分类不碰文案，
把后端异常 / 上游报错 / 网络错误归成 10 类：

```
channelMissing · auth · network · rateLimited · upstream
invalidParams · modelRemoved · canceled · modalRequired · unknown
```

识别规则全部基于代码里实际存在的字符串，不是猜的：
后端的 `请先配置.*渠道`、`Model (not found|disabled)`、`Invalid \w+`、
`validation.errors`，以及 axios 的 `Network Error` / `timeout of \d+ms`，
加上 401/403/429/5xx 状态码兜底。

`isConfigurationFailure()` 标出"重试再多次也不会成功、必须去补配置"的那几类。

**文案落在 `errors.failure.*`**（中英双语），每条都是归因 + 下一步，
该免责的明确免责：

> `上游限流了，与你的操作无关。等一会儿再试，或换一个渠道/模型。`
> `上游服务商这次没返回结果，与你的参数无关。可以直接重试，或换一个模型。`
> `连不上本地服务。确认后端已经启动，然后重试。`

原始报错不丢，走 sonner 的 `description` 挂在第二行（`上游返回：{detail}`）。
一开始用 `\n` 拼在正文里，但 sonner 不渲染换行，会挤成一行，所以改用 `description`。

**创作页**：提交失败改成分类后的可操作 toast，`duration: 8000`，
配置类失败带一个「去配置渠道」按钮直开 `SystemConfigModal`，
关闭时复用 A1 的 `modelsReloadToken` 重取模型。

**`TaskCard.tsx`**：失败原因也走同一个分类器。原先是
`CANCELED` / `MODEL_REMOVED` / `MODAL` 三个哨兵 + 其余直接摊出上游原文，
现在统一成「归因 + 上游返回：原文」。

顺带删掉 `tasks.json` 里被取代的 `failure.unknown` / `canceled` /
`modelRemoved` / `modalRequired` 四个 key —— 同一句文案留两处来源迟早会漂移。
`failure.reason`（"失败原因"标签）仍在用，保留。

### 性能约束（踩过的坑，别退回去）

- **3D 只能用 JS 投影，不能用 CSS 倾斜**：`rotateX` 倾斜整条轨道时图标会被拍平压扁（cos68°≈0.37）。
  现行做法（`ModelGlobe`）：JS 逐帧算每个图标在倾斜圆轨道上的 3D 坐标，只取正交投影的屏幕 x/y，
  图标永远正对屏幕；深度 z 只决定 scale（0.72–1.1）、opacity（0.35–1）和 z-index（1–19，低于文案的 20）。
  z-index 只在变化时写。轨道线是静态 SVG 椭圆（倾斜圆的正交投影），`vector-effect: non-scaling-stroke`。
- **文案避让**：图标进入球心文案区（半宽 150 × 半高 72，外加图标半宽）就淡到 15%，边缘 28px 软过渡。
- **悬停减速到停**：`hoveredRef` 控制，速度按 0.08 系数平滑趋近 0 / 1。
- 平面三圈旧版备份在 `frontend/.backup-globe-flat/`。
- **移动元素上不要 `backdrop-blur`**：十几个带 `backdrop-filter` 的元素是掉帧主因，用实心 `bg-white`。
- **hover 只过渡 `opacity`**：过渡全屏 `.auth-aurora` 的 `filter: blur()` 每帧重算，必卡。
  `box-shadow` 同理，改成静态阴影。放大 `scale(1.45)` / `200ms`。
- **放大做在 `.auth-orbit-tile` 上**，不能做在 `.auth-orbit3d-item` 上 ——
  后者的 transform 每帧被脚本改写，同一元素上两个 `transform` 会互相覆盖。
  悬停项用 `.auth-orbit3d-item:has(.auth-orbit-tile:hover)` 提到 z-index 40、opacity 1（`!important` 压过内联样式）。
- **容器全部 `pointer-events: none`**，只有 `.auth-orbit-tile` 是 `auto`：
  轨道和图标定位层都是 `absolute inset-0` 的透明满屏块，外圈最后渲染会盖住一切，
  不穿透的话鼠标永远命中容器、碰不到图标。
- 拖尾光效**已删除**，不要再加：全屏跟随重绘，用户实测卡。

### 验证纪律

Tailwind 任意值会**静默失效**，本节所有类名都必须对着编译产物核对：

```

```

已知两类失效：
1. `@tailwindcss/aspect-ratio` 插件**顶掉核心 `aspect-*`** —— `aspect-square` 不编译，

只有给人看的名字才跟着站点语言走。所以数据文件（`shotOptions.ts` / `promptLibrary.ts` / `presets.ts`）
现在**只存 key 和英文片段，不存中文名**，名字全部查 i18n。测试里专门有一条断言这 64 段片段不含中文。

#### 节点标题：不烤进数据，才能跟着切语言

原来 `addNode` 会把 `NODE_KIND_LABELS[kind]` 写进节点的 `data.title`，节点数据里就存了中文。
现在**不写 title**，由节点组件 `data.title ?? t('nodeKinds.<kind>')` 兜底显示——
没改过标题的节点会跟着语言变，用户改过的照旧保留。

预设铺开时**反过来**：显式把当前语言的标题和种子提示词写进节点。因为预设里的标题是具体名字
（「正面角色图（参考基准）」），不是节点类型名，用户接着还要自己改它，定住才对。

#### 纯函数不碰语言

两处返回值原来是拼好的中文，现在只给结构，文案由组件拼：
- `summarizeInputs` → `[{kind:'images',count:2}, …]`，因为中英量词位置不一样，拼成字符串就没法翻了。
- `parseProjectFile` → `{ok:false, code:'unsupportedVersion', version, max}`，
  校验是纯函数，不该依赖 React 上下文才能报错。
- `getOutputCountConfig` 的 `note` → `noteKey`（`'midjourney' | 'video' | null`）。

`aspectRatioOptions` 是创作页共用的，整份走 i18n 是另一件事，这次没动；
画布里只把 `value === ''` 那一项（写死的「默认」）换成当前语言。

#### 测试：`test-i18n.cjs`，14 条

页面上看不出漏翻——`useTranslations` 查不到 key 时返回 key 本身，界面会出现
`canvas.node.xxx` 这种字符串，**跑起来不报错**。所以静态查：
- 两份文案表 key 完全对齐、没有空串；
- `{count}` 这类占位符两边同名同数（否则一种语言里数字会凭空消失）；
- 把源码里的 `t('…')` 和 `t(\`…\${x}…\`)` 全扫出来，模板按真实数据展开
  （13 种节点 × 8 个预设 × 34 条素材 × 6 组镜头选项…），**239 个 key 全都有中英文案**；
- 反向查孤儿 key（只放行 `snippets.categories.custom`，留给以后的用户收藏）；
- 源码里不再有写死的中文字面量（注释不算）；
- 64 段 `promptFragment` / `content` 不含中文。

模板 key 还有一条自检：源码里出现了测试没覆盖的模板写法就直接失败，避免以后加了新模板悄悄漏掉。

#### 画布底色：黑 → 浅灰

用户：「画布背景不能是黑色 很不明显」。根因是画布底 `#090b0c` 和节点卡片 `#0f1213` 只差几档亮度，
卡片浮不起来，整片糊在一起。用户选了**浅灰底 + 深色卡片**（对比最强那一版）。

以及浮在画布上的缩放控件和缩略图（不转浅就是两块黑斑）。

### 2026-09-23 补：跟参考站逐条核对 + 圆角 + 左侧「助手」

用户：「你再核对一遍 目前画布的各个功能还有名称跟之前参考的那个站差不多吗 我感觉还是有区别」
「节点框架太四四方方了 圆润点会好看」「左侧的功能栏应该加个文本模型用来控制 点击节点就可以在左侧文本模型进行指挥」

#### 核对方法

参考站 `aivideo.token6688.com/zh-CN/agents/canvas-v2` 是 Next.js SSR，**整份 i18n 就在页面 HTML 的
flight 数据里**（1.6MB），不需要登录也不需要凭据。用括号配平从 `"assistantTitle"` 往外找到包住它的对象，
拿到画布命名空间 `workbench`：**700 个 key**（我们当时 239）。

用户记的是对的——`rail.assistantTitle` 原文就是

#### 圆角

`.cv2-root` 上加三档：`--cv2-r-card: 14px`（节点卡片、预设卡、右键菜单、占位框）、
`--cv2-r-control: 9px`（输入框、下拉、媒体、徽标）、`--cv2-r-chip: 999px`（标签、工具按钮、小圆点）。
原来全站都是 3–4px，所以看着四四方方。

#### 左侧「助手」

左侧栏改成两个标签：**搭积木**（原来的新建节点 + 工作流预设）和**助手**。

助手面板上半是**节点详情**——点中哪个节点就显示它的标题、类型和已填的设置；
下半是**对话指挥**：选文本模型（`modelService.getModels({type:'chat'})`），说一句话，
模型回一批动作，直接落到画布上。

复用站里现成的 `/chat/conversations` 会话接口，不另起一套——渠道路由、计费、失败分类都在那条路上。
会话一个画布页只建一次，所以连续几句话模型记得上文。

**两条硬规矩，写在代码注释里也写在界面上：**

1. **助手不许点生成。** 动作表里根本没有「运行」这个类型——模型真回了 `{"type":"run"}` 也会被当作
   非法动作丢掉（有测试盯着）。跑一次是真金白银的上游调用，那一下必须由人按。
   界面底部直说：「助手只会建节点、连线、填参数，不会替你点生成——跑一次是要花钱的，那一下由你按。」
2. **看不懂就整条丢掉。** 模型回的东西不可信：字段不在白名单（`status`/`taskId` 这类运行状态一律不许改）、
   值是对象、指向不存在的节点、ref 撞车、自己连自己——全部拒掉，并把条数显示给用户
   （悬停看原因），而不是静默吞掉或者照做。

**画布怎么讲给模型听**（`canvasDigest.ts`）：只给结构和可改字段，**媒体一律只说「有图/没图」**——
图片节点的 url 可能是几百 KB 的 base64，一个节点就能把上下文撑爆。字段超 200 字截断，节点超 40 个只讲前 40 个。
系统提示词写英文（跟 `promptFragment` 同理），并且明确要求写进 `prompt` 的内容必须是英文。

#### 测试

**`test-as.cjs` 33 条**：围栏 ```json 剥离、混在解释文字里挑 JSON、字符串里的花括号和转义引号不干扰；
截断 JSON / 非法内容 / 没有 actions 各自分得开；不许改 `status`、`taskId`；
**`run` 不是合法动作**；一条坏的不影响后面的好动作；同批 `add` 的 ref 能被后面 `set`/`connect` 引用并换成真 id；
多个新节点不叠在一起；摘要不含 base64（50KB 的 data URL 进去，摘要仍 < 600 字符）、超长字段截断、
120 个节点只讲前 40 个；系统提示词是英文且含「不能点生成」。

`test-i18n.cjs` 本轮**自己抓到了漏网**：新加的 `sidebar.tabs.${tab}`、`assistant.field.${row.field}`
一开始没被展开规则覆盖，那条「没有测试没覆盖到的模板 key」直接失败了——这正是当初加它的原因。
补上后 266 个 key 全都有中英文案、零孤儿。
